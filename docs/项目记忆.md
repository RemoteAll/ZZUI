- **停靠族三个必踩坑（2026-11-10 实测）**：
  ① **新面板不能一律塞「根叶子的第一个叶子」** —— `begin` 建默认布局时还不知道有哪些面板，

### 里程碑 1 结构与实现要点
- 分层：`types/theme/core/render/widgets` 平台无关；`platform.zig` 联合体（`win32`/`null_backend`）分发；`platform/win32.zig` 实现窗口 + DIB + 系统字体 + BitBlt；`platform/null.zig` 无窗口（`--once`/单测）。

### Zig 0.17 踩坑（本轮实测）
- `std.lang.Optimize` 枚举值**小写**：`.debug/.safe/.fast/.small`（无 `.ReleaseSmall`）。
- 数组重复 `a ** n` 已移除 → `@splat(v)`。
- **`std.fs.cwd()` 不存在**（新 IO 模型 `std.Io.Dir` + `Io` 实例）→ 文件写入走 Win32 `CreateFileW/WriteFile`（`src/bmpfile.zig`）。
- 对 `*union(enum)` 写 `switch (self) { .x => |*b| }` 捕获到的是标签指针 → 必须 `switch (self.*)`。
- `SelectObject` 返回 `?HANDLE`，恢复旧对象要 `orelse`。
- 测试断言别假设「容器会出绘制指令」：无填充容器只产生节点，不出 rect 指令。
- **胶囊圆角 `radius=999` 会让整块不画**：`fillRoundRect` 的角点判定在半径大于短边一半时恒不成立 → 半径必须夹到短边一半。
- **节点里的文本 slice 必须来自帧内池**：控件栈上的临时 `buf`（如 `textIntRun` 拼的数字）在帧末绘制前已失效，会渲染成乱码；
  `textRun` 统一 `frameStr` 拷贝（CUI 的 `cui__frame_strdup` 口径）。
- `defer row.end()` 覆盖整个函数体：后面还有兄弟控件时，会把它们塞进这一行；用 `{ var row = ...; defer row.end(); ... }` 限作用域。
- **值接收的方法返回内部 slice 会指向副本**：`charsSlice(self: Input)` 导致插入内容全 0，必须 `self: *const Input`。
- 同帧内「按键 + 字符」要按 KEYDOWN→WM_CHAR 顺序处理：先导航/编辑键，再插入字符，否则 `End`+输入会插错位置。
- 像素断言别写死坐标：文本换行会改动高度/位置，改成在区域里扫描颜色（本轮把 (100,170) 改成 y=80..320 扫描）。
- **点击目标在 `begin` 里从上一帧命中算**（`click_target`）：调用方/测试必须 **begin 之前** 设置 `input`，否则点击不生效。
- 浮层用 absolute 帧：`close()` 不推进父容器游标，否则弹窗会把页面内容推下去。
- **文本不能统一最后画**：页面文字会浮在弹窗之上；必须按层交错输出「矩形→文本」（`layer` 指令）。
- **absolute 面板不能在 `close()` 里重算矩形**：会被内容高度覆盖，卡片变矮、按钮掉到卡外。
- **改含中文的 `.ps1` 不能丢 BOM**：`WriteAllText(UTF8Encoding($false))` 会删 BOM，PS 5.1 按 ANSI 读 → 中文路径乱码、回归误报；改完补回 BOM。
- 按键要在 `begin()` **之前**注入（`begin` 里消费 Tab），单测里写成 begin 后 addKey 会静默失效。
- **参数名不能与同文件公开函数同名**：`tooltip(..., text: []const u8, ...)` 报 `function parameter shadows declaration of 'text'` → 改名 `label`。
- **悬停类延时交互要三帧才可见**：第 1 帧 `hovered=false` 复位、第 2 帧记起点、第 3 帧 `time-start>=delay` 才画；
  截图脚本要显式刷三帧并设 `ui.time`（headless `now()` 恒 0，不会自己涨）。
- 提示层必须 `hit=false`：沿用 `hit=true` 会吃掉按钮点击（提示正好盖在悬停目标上）。
- **`row` 里不能放 `column`/`card`**：`open()` 取 `outer_w = parent.width`，嵌在 row 里会各占整行宽 → 卡片溢出窗口。
  卡片只在 column 用；row 内要绝对定位就用 `panel`。
- **同名按钮会撞交互 id**：`buttonRect` 用 `idOf(label)`，分页 `<`/`>`、步进器 `-`/`+` 多实例会互抢点击 → 用 `ButtonOpts.id_salt`。
- **`u0`/`u1`/`f16` 类是 Zig 原生整型名**，局部变量这样命名直接编译失败（改 `f0`/`f1`）。
- **拖拽类单测必须给 `input.pressed`**：只设 `down = true` 不建立 `active_id`，第二帧拿不到 `dragging`。
- **`--once` 是 headless，不画文字**：只能验布局尺寸；文字排版必须 `--shot`（Win32 GDI）。窗口高受屏幕限制
  （请求 1600 只得到 961）→ `--shot-bottom` 先滚到底再拍。
- **浮层锚点常在滚动视口之外**：popover 定位必须 `clamp(y, 8, height-8-estimate_h)`；只做「空间不足翻上方」会把面板画到窗口外（截图完全看不到）。
- **`input.click` 会跨帧残留**：Win32 `poll()` 原来只在有 pending click 时赋值不清空 → 同一位置每帧重复命中；已改逐帧重置 `click`/`right_click`。
- **「未开始」哨兵不能用 0**：headless 首帧 `ui.time` 就是 0，`since==0` 会反复重置；用 **-1**。
- **`search` 这类控件不能只返回 bool**：清除内容与「按了 Enter」是两件事，合成一个返回值必然误判 → 返回结构体（`SearchResult{changed,submitted}`，对齐 CUI 的 CHANGED/SUBMITTED 标志位）。
- **`textarea` 的点击定位会覆盖调用方光标**：单测「先点击取焦点再退格」会把光标重置到首行行首，退格就删不到换行 → 要显式把光标设回目标位置。
- **`\n` 只是普通字符**：跨行删除不需要特殊分支（退格删前一个字节正好是换行），不要为此写第二套逻辑。
- **`align` 是 Zig 关键字**，不能当字段名（`text_align`）；同理 `Type.field` 不能当常量 → 用命名空间常量（`tree_indent`）。
- **`defer tbl.end()` 会覆盖整个函数体**：同一块里紧跟的控件会被塞进表格滚动区（截图只剩一行且串位）→ 表格必须用 `{ }` 限作用域。
- **嵌套滚动区会重复消费滚轮**：`scroll()` 原用本帧矩形判 hover，页面滚完内容立刻位移、内层恰好落到鼠标下 → 同帧内外层都滚。
  已修：hover 用上一帧矩形（`prevHitRect`）+ `wheel_target`（上一帧最内层）+ `wheel_used`（一帧一次）；查询用 `Context.scrollOffset(id)`。
- **★ 体积红线（2026-11-10 实测）**：
  - `std.fmt` 的浮点格式（`{d:.2}` / `{d}` 传 f32）会把整套浮点格式化拉进产物（几十 KB）→ 用 `num.fixed/int/percent`（整数定点）。
  - **容量常量直接换体积**：`MAX_NODES` 256→512（连同 COMMANDS/HITS/OVERLAYS）让 hello x64 **173,568 → 252,928 B（+79 KB）**；
    改回小容量立刻回落。**不要为了让一个演示页塞满控件而扩容**——分页/拆屏才是正解。
  - `Context.overflowed` 会在节点/指令/线段/命中溢出时置位；画廊 `--once`/`--shot-N` 以退出码 8 失败，回归能发现「莫名少画」。
- **面积填充不能逐像素 `addBox`**（600px = 300 节点，吃光 `MAX_NODES`，后面整块不画）→ 每 12px 一条粗线段（`addOverlayLine` 宽度=步长）。
- **圆弧要算线段预算**：`MAX_OVERLAYS` 192，一页里 sparkline 填充 + 折线 + 网格 + 环形 + 仪表会超 → 圆弧 20 段/圈、半圆 14 段、填充步长 12。
- **★ 审计实测（2026-11-10）：线段预算比节点预算先满**。`table + charts` 同页时 `lines=192/192` 被打满，界面「图表缺一块」；
  冒烟测试 + `markOverflow` 的 Debug 打印 5 秒内指出是 `overlays`。修法：**面积填充改宽矩形条**（每 20px 一条，占节点不占线段），
  圆弧收到 16 段/圈、半圆 12 段 → 修后 `nodes=152/256 cmds=266/512 lines=83/192`。
- **`MAX_OVERLAYS` 192→384 实测让 hello x64 +13,824 B（+13.5 KB）** → 不要靠扩容解决绘制预算，要降绘制成本。
- **`markOverflow(where)` 用 `if (@import("builtin").mode == .debug)` 打印**：0.17 的 `Optimize` 枚举是**小写**（`.debug`），
  发布构建不生成字符串，体积实测不变。
- **`ui.reserve()` 之后不能紧跟 `ui.row()`**（2026-11-10 chrome 首版）：reserve 已推进父游标，随后的 row 从推进后位置开始 →
  背景条与内容错开一整条高。外壳件（菜单栏/工具栏/标签条/状态栏）要在**已占位的矩形内**布局 → 用 `ui.panel(rect, ...)`。
- **`PanelOpts.dir` 默认是 column**：横向条（菜单栏/工具栏/标签条）必须显式 `.dir = .row`，否则元素竖排。**同轮连踩两个布局坑，靠截图才看出来。**
- **下拉/浮层不能一个函数画两段**：字段在页面阶段、弹层在浮层阶段（否则弹层落在页面流里且被后续控件覆盖）。

### PowerShell 5.1 踩坑（本轮实测）
- **`& exe` 不等 GUI 子系统程序**：立即返回、`$LASTEXITCODE` 是假值（本轮实测退出 0 但文件还没写）。
  取真实退出码必须 `Start-Process -PassThru -Wait`（可配 `-WorkingDirectory`、重定向到临时文件读输出）。
- **`Push-Location` 不改进程级 cwd**：`[Environment]::CurrentDirectory` 仍是启动目录，原生子进程继承的也是它；
  要让子进程在指定目录运行，显式 `[Environment]::CurrentDirectory = (Get-Location).Path` 并在结束后还原。
  同一坑会导致相对路径的 `[IO.File]::ReadAllBytes('tools/...')` 解析到错误目录。
