## 2026-11-10 · 接入全局用户指令与接续基建

**用户原话**：
> 「先帮我接入全局用户指令和迁移续接相关的处理」

**背景**：`g:\Code\Zig\ZZUI` 是 `git init` 后的空仓库（无提交、无代码、无 remote），需要先按《跨项目接续协议》装备接续基建，保证跨电脑 / 跨会话可接续。

**决策与落地**：
1. **用户级指令**：把已验证模板 `tools/continuity/templates/用户级指令.instructions.md`（版本 **2026.11.09.2**，SHA256 `5B6EE71F…`）随仓库版本化；`install-global-instruction.ps1` 幂等安装到 `%APPDATA%\Code\User\prompts\跨项目接续协议.instructions.md`，带版本守卫（旧副本不覆盖新副本）。
   - 模板来源核对：`G:\Code\Zig\ZZCOM`、`G:\Code\Rust\Pek.RMail` 与本机副本三者 **SHA256 完全一致**，取最新未漂移副本，未做任何内容改动，故**不递增版本号**。
2. **记忆同步脚本**：采用 `ZZCOM` 的较新版本（7600 B，2026-11-05 合并规则：**只把小节标题形如 `*.md` 的当边界**，正文里的 `##` 标题不再切碎镜像；并把连续空行归一化）。`Pek.RMail` 的 6247 B 旧版按行首 `## ` 切分，已知会拆碎镜像，故不采用。
3. **一键回归**：新建 `tools/regression.ps1`；当前无 `build.zig`，脚本显式输出 `SKIP` 并给出原因（不静默 `return`），`zig build` 就绪后自动接管。
4. **自检任务**：`.vscode/tasks.json` 配 `runOn: folderOpen`，打开项目自动跑接续自检（双保险）。
5. **不复制跨仓同步工具**：`_sync-user-instruction.ps1` / `_commit-user-instruction.ps1` 属于 `Pek.RPanlServer\tools\continuity\` 的全盘同步工具（历史教训：硬编码路径导致 110 个副本版本参差），**不在各仓库留副本**，避免次生漂移源。

**验证结果（实测输出）**：
- `install-global-instruction.ps1` → `OK：已是最新（版本 2026.11.09.2），无需操作`，exit 0。
- `sync-memory.ps1` → `[记忆同步] 本地记忆 1 个；保留镜像小节 0 个 -> docs\项目记忆.md`，exit 0。
- `tools/regression.ps1` → `REGRESSION PASSED (skip=2)`，exit 0：`zig-version`=0.17.0 PASS，接续三件套 PASS，自检实跑 PASS，6 份文档 PASS；`zig-build` / `zig-test` 因无 `build.zig` 打 SKIP（原因写明，非静默跳过）。
- 换行核对：模板 266 行全 LF（45688 B），工作副本、仓库 blob、本机 `跨项目接续协议.instructions.md` 三者 SHA256 一致（`5B6EE71F…`）→ 克隆后不会因换行归一化导致哈希漂移、误触「UPDATED」。

**待确认（未落成结论）**：首个交付目标与远端仓库地址（项目定位已于下一节确认）。
