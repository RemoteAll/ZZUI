1. 低风险搬运：`src/win32/{types,const,ui,gdi}.zig` + 空窗口样例，`zig build` 通过；

## 2026-11-10 · 新约束：CUI（C 版）用 Zig 重写，产物体积尽可能小

**用户原话**：
> 「G:\Code\C\CUI  这个我我也想用Zig重写，但所有的都是需要打包后的尺寸都是要尽可能的小。」

**对象实测**（`G:\Code\C\CUI`，上游 `yappologistic/CUI`，MIT 许可，本地 `master` = `e8688b8`）：
- 规模：`src/*.c` **61 个文件 52,290 行**；`include/*.h` 4 个 **3,708 行**（`cui.h` 单文件 241 KB）；`third_party` 577 KB（`stb_image` / `stb_image_write` / `stb_rect_pack` / `stb_truetype`）。
- 形态：C99 **立即模式** UI 库，自述「约 190 个组件」；软件渲染器 + OpenGL 渲染器；后端 Win32 / Cocoa / X11 / SDL2 / GLFW。
- 上游体积纪律（`docs/architecture.md:158`）：每加代码都要量 `examples/hello` 在 `MinSizeRel` 下的增量；**核心不直接调用组件文件**（Windows 链接器按文件整体保留），可选功能由组件自己装 hook（如 `ui->emoji_hook`）。

**体积基线（本机实测，不是引用）**：
- 工具链：`zig cc`（Clang 22.1.8）+ CMake + Ninja，`-Os -DNDEBUG -Wl,--gc-sections -mwindows`，`MinSizeRel`，**无 LTO**（zig 链接器不接受 `-flto=auto`，已剔除后重建）。
- `examples/hello.exe` = **303,104 B（296.0 KB）**；加 `-s` 后字节数不变 → 无调试符号可剥。
- `libcui.a` = 2,167,792 B（2,117 KB）→ 体积靠链接期丢弃未用组件，库本身很大。
- 上游 README 自述「完整应用约 250 KB」，与实测 296 KB 同量级（差异来自缺 LTO 与编译器不同）。

**结论**：
1. **体积是第一约束**：以后每个 Zig 产物都要设体积上限，阈值写进回归脚本、只能收紧；每轮提交必须报实测字节数。
2. Zig 侧可行手段（**待逐个实测**，不预设结论）：`ReleaseSmall` + `strip`（ZZCOM 已验证）、GUI 子系统、不链 libc、按模块分文件避免整文件被保留、可选功能走 hook、数据表压缩（字体/emoji 走 `std.compress.flate`）。
3. **规模现实**：52,290 行 C、约 190 个组件，不可能一次搬完；必须分批，每批用 `zig build` + 体积对照卡住。

**待用户确认**（未落成结论）：
- ① CUI 是否作为 **ZZUI 的移植蓝本**（即 ZZUI 就是 CUI 的 Zig 版），还是另起独立仓库；
- ② 首批范围：骨架 + hello 等价物 / 核心组件子集（列出名单）/ 按目录逐个搬；
- ③ 平台范围：只做 Win32，还是保留多平台抽象。

## 2026-11-10 · 确认蓝本并要求多平台；里程碑 1 落地

**用户原话**：
> 「确认作为蓝本，现在开始」
> 「要做多平台的」

**决策**：
1. **CUI 是 ZZUI 的移植蓝本**；首批 = 骨架 + hello 等价物（与 `examples/hello.c` 同构）。
2. **必须多平台**：平台差异全部收敛到 `src/platform/*`，`core / render / widgets` 不引用任何平台 API；`platform.Backend` 用联合体分发，新增平台 = 加一个成员 + 一组同名方法。
3. **API 形态**：立即模式（CUI 原生形态的本味移植）——控件是函数、状态在调用方变量、输入对**上一帧矩形**判定。
4. **文本渲染取舍（体积优先）**：里程碑 1 由平台层用系统字体绘制（Win32 GDI），核心只发 `text` 指令；**不内嵌字体、不带 TTF 光栅器**。代价是跨平台视觉不完全一致；是否改为核心自带 TTF 光栅 + 内嵌字体列为待确认。

**里程碑 1 实际落地（文件清单）**：
- `build.zig`：x64 + x86 两个 exe，`optimize` 默认 `.small`（Zig 0.17 改为小写枚举）、`strip = true`、`subsystem = .windows`、`.abi = .gnu`（不链 libc）。
- `src/types.zig` / `theme.zig` / `core.zig`（节点、栈布局、绘制指令、命中判定、FNV-1a id）/ `render.zig`（BGRA 软件光栅、圆角）/ `widgets.zig`（heading / text / secondary / button / switch）/ `platform.zig` + `platform/win32.zig` + `platform/null.zig` / `bmpfile.zig`（Win32 落盘）。
- `src/win32.zig`：**复用 ZZCOM 已实测的 Win32 声明层**（681 行 → 追加 DIB/文本/鼠标消息），避免重写 100+ 个 extern。
- `examples/hello.zig`：窗口版 + `--once` 无窗口出图（写 `zzui-hello.bmp`）。

**实测（本机，2026-11-10）**：

| `zig build` | exit 0 |
| `zig build test` | 3 个单测通过（column 栈叠、row 主轴、上一帧点击判定） |

| 一键回归 | `REGRESSION PASSED (skip=0)`（含体积门槛与像素断言） |

**Zig 0.17 实际踩坑（写进记忆，避免下次重复）**：
- `std.lang.Optimize` 枚举值改为小写 `.debug/.safe/.fast/.small`（不再有 `.ReleaseSmall`）。
- 数组重复 `**` 已移除 → `@splat(...)`。
- `std.fs.cwd()` 在 0.17 不存在（新 IO 模型走 `std.Io.Dir` + `Io` 实例）→ 里程碑 1 的 BMP 落盘改用 `CreateFileW/WriteFile`（`src/bmpfile.zig`）。
- 对 `*union(enum)` 做 `switch (self)` 时 `|*b|` 捕获的是标签指针 → 要写 `switch (self.*)`。
- `SelectObject` 返回 `?HANDLE`，恢复旧对象要 `orelse`。

**与 CUI 的已知差异（里程碑 1 明确不做，后续对齐）**：
- 布局在构建时放置（CUI 是帧末统一布局 + 上一帧矩形回读）；
- 无状态回收、无弹簧动画、无深色主题、无键盘焦点/无障碍；
- 单窗口、无浮动层（popover/dialog）、无 OpenGL 渲染器；
- 只有 5 个控件，CUI 约 190 个。

**下一步（按体积门槛逐批推进）**：Cocoa / X11 后端 → 帧末布局与动画 → 基础控件族（checkbox/radio/slider/input）→ 容器与滚动 → 浮层（menu/dialog/tooltip）。

1. **`row` 里不能放 `column`（含 `card`）**：`open()` 取 `outer_w = parent.width`，嵌在 row 里会各占整行宽 → 卡片直接溢出窗口（首版 `metric` 就这样冲出了右边界）。卡片只在 column 里用，row 里要用绝对定位的 `panel`。

## 2026-11-10 · 表格族落地（table / treeTable）+ 嵌套滚动只滚最内层

**用户原话**：
> 「请继续」

**落地**（新增 `src/table.zig`）：
- `begin(ui, id, columns, sort*, opts) -> Table` / `Table.row(index, selected) -> Row` / `Row.cell(idx)` / `Row.text(idx, s, color)` / `Table.end()`：
  - **流式**形状（与 CUI 的 `cui_table_begin/row/cell/end` 同构）：行矩形一次占位，单元格按列宽**纯计算切片**，
    所以单元格里可以放任意绘制内容（不只是字符串）；
  - 列：固定宽 / 弹性列（`width = 0` 吃掉剩余宽度，多弹性列平均分）、`text_align`（`align` 是 Zig 关键字）、`sortable`；
  - 列头点击切换排序（升 → 降 → 换列），并画出 ▲/▼ 指示；
  - 行：选中底色、hover、斑马纹、1px 分隔线；`opts.height > 0` 时正文区滚动（**表头固定**），复用 `ui.scroll`。
- 树形表格：`treeRow(tbl, index, *TreeRow, label, selected) -> TreeResult{row, toggled}` ——
  缩进（`tree_indent = 16`）+ 展开三角（▸/▾，点击只切换展开、不触发行点击），返回行句柄以便继续 `row.text(1, ...)` 画其它列。
- 核心修复（本轮真 bug）：**嵌套滚动区会把滚轮重复消费**。`scroll()` 原来用「本帧矩形」判 hover，
  页面滚动后内容立即位移，内层（表格）恰好落到鼠标下 → 同一帧内页面与表格都滚。
  改为：hover 用**上一帧**矩形（`Context.prevHitRect`），并用 `wheel_target`（上一帧最内层 hover 的滚动区）
  + `wheel_used`（一帧只消费一次）保证滚轮只作用于最内层；新增 `Context.scrollOffset(id)` 供虚拟列表与测试查询。

**实测**：
| 项 | 结果 |
|---|---|
| `zig build test` | **38 项通过**（新增 4 项：行点击、单元格切片（弹性 320 + 固定 80 且相邻不重叠）、可排序表头切换升/降、树表三角只切展开不改选中，以及**嵌套滚动帧 1 只滚外层/帧 2 只滚内层**） |
| 体积 | hello x64 **173,568 B（169.5 KB）**、x86 **174,080 B（170 KB）**、gallery x64 **205,312 B（200.5 KB）**（门槛 303,104 B，占 68%） |
| 截图 | 数据表 6 行（首行 api-gateway 起）、状态色（running 绿 / degraded 橙 / stopped 红）、Latency 右对齐、表格内滚动条；树表 4 行缩进与 ▾/▸ 正确 |
| 回归 | `REGRESSION PASSED (skip=0)` |

**踩坑**：
1. **`align` 是 Zig 关键字**，不能当字段名 → `text_align`（与 `align` 属性冲突的还有 `align`/`fn`/`type` 等）。
2. **`Table` 的 `defer tbl.end()` 会覆盖整个函数体**：同一块里紧跟的 heading 与第二个表格都会被塞进第一个表格的滚动区
   （首版截图只剩一行、且串位）。**表格必须用 `{ }` 限定作用域**。
3. **嵌套滚动 → 滚轮被内外层同时消费**：页面滚动后内容立刻位移，内层滚动区「移动到鼠标下」被同一帧再滚一次。
   修法见上（上一帧矩形 + 单一消费者 + `wheel_target`）。
4. **`TreeOpts.indent` 这种「想当常量用」的结构体字段**在 Zig 里必须 `Type{}.indent` 或改用命名空间常量（本轮改为 `tree_indent`）。

**已知差异**：列宽不可拖拽调整、无多选/复选框列、无固定列、无单元格内联编辑（可直接在 cell 里放 `textedit` 组件实现）、
`treeRow` 不做父子折叠联动（可见性由调用方按 `expanded` 自行过滤）。
