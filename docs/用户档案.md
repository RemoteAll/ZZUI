## 决策口径（含用户原话）

- 2026-11-10：开工第一件事是**接入全局用户指令 + 迁移/续接处理**，先把接续基建铺好，再谈代码。
  > 「先帮我接入全局用户指令和迁移续接相关的处理」
- 2026-11-10：项目定位 = **ZigLang 的 UI 界面框架**。
  > 「当前这个项目主要是用于ZigLang开发的UI界面框架」
- 2026-11-10：**体积是硬约束**——CUI（`G:\Code\C\CUI`）要用 Zig 重写，所有打包产物尺寸都要尽可能小。
  > 「G:\Code\C\CUI  这个我我也想用Zig重写，但所有的都是需要打包后的尺寸都是要尽可能的小。」
  落地口径：每个产物都设体积上限（阈值只能收紧）；提交时汇报实测字节数；新增依赖/模板实例化先算体积账。
- 2026-11-10：**必须多平台**（不能只做 Win32）。
  > 「要做多平台的」
  落地口径：平台差异只能在 `src/platform/*`；core / render / widgets 不得引用平台 API。
- 沿用通用口径：**复用优先**（先查 `G:\Code\Zig\ZZCOM` 等兄弟 Zig 项目、`G:\Code\Zig\skills` 与本仓既有实现，再新写）；**实测优先**（性能/行为结论必须带命令与输出）；**分档验证**（`zig build` 验证，仅在用户明确说打包时才打包）。
